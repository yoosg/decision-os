# 입문자 카드 — 통합 바이브코딩 가이드 (P3) 설계

- 날짜: 2026-08-31
- 슬라이스: 입문자 프로젝트 카드 3b 재정의 중 **P3 (통합 가이드라인)**
- 브랜치(예정): `feat/beginner-card-vibecoding-guide` (현재 `feat/beginner-card-content-depth`에서 커밋 전 rename 예정)
- 관련 메모리: `beginner-card-next-steps`, `web-bottom-fixed-bars-convention`, `web-test-runner-vitest`

## 배경 / 목적

입문자 프로젝트 카드의 목표를 **"카드 하나만 보면 실제로 바이브코딩을 완주할 수 있게"**로 재정의하면서,
원래 "3b 프롬프트 심화"가 세 조각으로 분해됐다:

- **P1 마일스톤 프로세스화** — 서비스별 스텝 → 고정 프로세스 백본 + 카드별 힌트 (백엔드 스키마·프롬프트 + 프론트)
- **P2 체크리스트 → 요구사항/MVP 챌린지** (백엔드 프롬프트 + 프론트 문구)
- **P3 통합 가이드라인** — Claude Code 환경 설정 + 바이브코딩 흐름을, 카드마다 반복되는 **정적 공용 블록**으로 노출 (프론트 전용)

본 문서는 **P3만** 다룬다. P1/P2는 별도 슬라이스(각자 spec→plan→구현). 섞지 않는다.

P3를 먼저 하는 이유: (1) 프론트 정적이라 빠르고 리스크 낮음, (2) 여기서 확정하는 **"바이브코딩 흐름 6단계"가 P1 마일스톤 백본으로 그대로 재사용**되므로 흐름 어휘를 선확정하는 이득, (3) 입문자에게 "Claude Code 어떻게 켜지 / 흐름이 뭐지"가 가장 먼저 필요한 정보.

## 범위

### In scope (P3)
- 카드 상단에 **단일 fold** 형태의 통합 가이드 컴포넌트 신설
- 정적 콘텐츠 2섹션: (A) Claude Code 켜기, (B) 바이브코딩 흐름 6단계
- 첫 방문 자동 펼침 (localStorage 전역 플래그)
- `project_card` 카드가 뜨는 모든 화면에 노출 (홈·큐·스탠드얼론·체인상세)

### Out of scope (명시적 비목표)
- **백엔드/스키마/프롬프트 변경 없음** (LLM은 이 콘텐츠를 생성하지 않는다 — 전부 정적)
- P1(마일스톤 구조 변경), P2(체크리스트 요구사항화)는 손대지 않음
- 리서치 리뷰(13섹션) 화면에는 표시하지 않음
- 개인화/A·B 테스트 없음 (표준 동일 콘텐츠)

## 설계

### 컴포넌트
- 신규: `web/src/components/home/review/vibe-coding-guide.tsx` — `VibeCodingGuide` (client component)
- 정적 콘텐츠는 같은 파일 내 상수로 시작. **B의 6단계 백본**은 P1에서 재사용되므로, P1 착수 시 공용 상수(예: `vibe-coding-flow.ts`)로 추출 예정 — P3에서는 아직 분리하지 않음(YAGNI, 단 주석으로 재사용 의도 표기).

### 배치 (Placement)
- 카드 **최상단**, `ProjectCardMeta`(난이도 뱃지 줄) **위**에 렌더.
- 삽입 지점 2곳 (둘 다 `<ProjectCardMeta/>` 앞에 `<VibeCodingGuide/>` 추가):
  1. `web/src/components/home/review/project-card-content.tsx` (홈·큐·스탠드얼론)
  2. `web/src/components/history/chain-detail-content.tsx` (체인상세, 읽기전용)
- 체인상세는 읽기전용 히스토리지만 가이드는 순수 정보성이라 동일 노출(일관성). 진도/체크와 달리 상태 저장 없음.

### 인터랙션 / 상태
- fold 헤더: `🧭 바이브코딩 가이드` + 펼치기/접기 토글 (`aria-expanded`로 접근성).
- **첫 방문 자동 펼침**:
  - `localStorage['vibecoding_guide_seen']` 부재 → 펼친 상태로 초기 렌더 + 즉시 플래그 세팅.
  - 플래그 존재 → 접힌 상태로 초기 렌더.
  - 이후 사용자가 토글로 자유롭게 여닫음 (수동 토글 상태는 별도 영속화하지 않음 — 세션/렌더 한정).
  - 플래그는 **전역**(카드별 아님). 가이드 내용이 모든 카드에 동일하므로 한 번 보면 이후 카드에서도 접힘.
- SSR/hydration 주의: `localStorage`는 클라이언트에서만 접근 가능. 초기값은 접힘으로 렌더 후 `useEffect`에서 첫 방문이면 펼치도록 처리하여 hydration mismatch 회피(구현 세부는 plan에서).

### 데이터 흐름
- 백엔드 호출 없음. 전량 정적 상수 + localStorage. API/스키마/DB 무변경.

## 콘텐츠 (확정 초안)

### 🧰 섹션 A — 처음이라면: Claude Code 켜기
1. **설치** — 터미널에 `npm install -g @anthropic-ai/claude-code` (또는 데스크톱 앱 설치)
2. **로그인** — `claude` 실행 후 화면 안내대로 로그인
3. **폴더 열기** — 프로젝트 폴더를 만들고 그 안에서 `claude` 실행
4. **첫 프롬프트** — 카드의 '예시 프롬프트'를 그대로 붙여넣기

> 설치 명령/로그인 절차는 구현 시 현재 Claude Code 공식 방식으로 1회 검증 후 확정한다.

### 🧭 섹션 B — 바이브코딩은 이렇게 흘러가요 (6단계 백본)
1. **브레인스토밍** — "이 아이디어로 뭘 만들 수 있어?" Claude에게 옵션 펼쳐달라 하기
2. **구체화** — 그중 하나를 골라 한 문장으로 좁히기
3. **기획·설계** — 필요한 화면·데이터·기능을 목록으로 적기
4. **개발** — 화면부터 만들고, 그다음 기능 붙이기
5. **테스트** — 직접 써보며 안 되는 걸 Claude에게 고쳐달라 하기
6. **마무리·다음** — 정리하고 "다음엔 뭘 더 해볼까?" 물어보기

발산(브레인스토밍)→수렴(구체화) 순서로 bmad식 흐름과 정합. **이 6단계는 P1 마일스톤 백본과 동일하게 사용된다.**

## 접근성 / 스타일
- 토글 버튼: `<button aria-expanded>` 사용, 키보드 포커스 가능.
- 기존 카드 모노크롬 폴리시(PR #7)와 톤 일치: 담백한 박스, 검정 액센트 계열. 인라인 스타일 컨벤션(주변 카드 블록과 동일) 따름.
- 하단 고정 바 관련 없음(상단 요소).

## 테스트 / 검증
- 이 브랜치의 웹 러너 여부를 먼저 확인(`web-test-runner-vitest` 메모리: 브랜치 의존적). 러너 있으면 컴포넌트 테스트 실행, 없으면 비실행 `*.test.tsx` + `tsc` 타입체크 + Playwright 라이브 확인.
- 최소 검증 항목:
  - 첫 방문(localStorage 비움) → 가이드 펼쳐짐 + 플래그 세팅됨.
  - 재방문(플래그 존재) → 접힘.
  - 토글 동작(펼침↔접힘, `aria-expanded` 반영).
  - `project_card` 카드에만 노출, 리서치 리뷰엔 미노출.
  - 홈/큐/스탠드얼론/체인상세 4경로 렌더 (기존 카드 회귀 없음).
- 라이브 확인용으로 심어둔 시드 카드(review `ac38f504-…`, signal `ccb42703-…`) 활용 가능. 검증 후 정리.

## 리스크 / 열린 항목
- **자동 펼침 hydration**: SSR 접힘 → 클라 첫방문 펼침 전환 시 깜빡임 가능. `useEffect` 지연 전개로 처리, 미미하면 허용.
- **설치 명령 정확성**: 섹션 A 명령은 구현 시 재검증 필요(위 표기).
- **체인상세 노출 여부**: 현재 노출로 설계. 히스토리에선 불필요하다는 판단이 서면 plan 단계에서 제외 가능(1줄 차이).
