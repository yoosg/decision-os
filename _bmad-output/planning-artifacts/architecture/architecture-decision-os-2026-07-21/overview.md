# Decision OS 아키텍처 개요

> 이 문서는 기술 배경이 없는 독자도 시스템의 구조와 설계 이유를 이해할 수 있도록 작성됐습니다.

---

## 한 줄 요약

Decision OS는 **사용자의 중요한 결정을 AI가 검토하고, 기록하고, 학습하는 개인 의사결정 도우미**입니다. 보험을 시작으로 커리어·투자·주거 등 다양한 도메인으로 확장됩니다.

---

## 시스템이 하는 일

모든 기능은 하나의 루프를 중심으로 돌아갑니다.

```
Review (AI 검토)
    ↓
Decision (사용자 선택 기록)
    ↓
Outcome (결과 추적)
    ↓
(다음 Review에 맥락으로 반영)
```

예를 들어 보험에서는:
1. 사용자가 병원 영수증을 올린다
2. AI가 "이 치료비, 어떤 보험으로 청구할 수 있는지" 분석해 리포트를 만든다
3. 사용자가 청구 여부를 결정하고 기록한다
4. 나중에 실제로 보험금을 받았는지 결과를 입력한다
5. 이 경험이 다음 AI 분석에 반영된다

---

## 핵심 개념 세 가지

### 1. Playbook
도메인별 분석 규칙 묶음입니다. 보험·커리어·투자가 각각 다른 Playbook을 사용하지만, 공통 루프(Review→Decision→Outcome) 위에서 동작합니다.

### 2. Project
한 사람의 지속적인 의사결정 공간입니다.
- 보험 Project: "내 보험 관리" — 장기간 여러 Review가 누적
- 커리어 Project: "2026년 이직 준비" — 목표와 종료 시점이 있음

### 3. Memory *(향후 도입)*
과거 결정에서 추출한 장기 맥락입니다. "이 사람은 보험료 20만 원 이하를 선호한다", "연봉보다 기술 성장을 중시한다" 같은 정보를 저장해 AI가 더 개인화된 분석을 제공합니다. MVP에서는 도입하지 않고 실제 사용 패턴을 확인한 뒤 추가합니다.

## 시스템 구성

세 개의 주요 부품으로 이뤄져 있습니다.

```
┌─────────────────────────────────────────────┐
│                사용자 브라우저               │
└───────────────────┬─────────────────────────┘
                    │
        ┌───────────▼───────────┐
        │      Next.js 앱       │  ← 사용자가 보는 화면
        │    (화면·인터페이스)   │
        └──────┬────────┬───────┘
               │        │
    화면 데이터  │        │  AI 분석 요청
    직접 조회   │        │  데이터 저장
               ▼        ▼
    ┌──────────────┐  ┌─────────────────┐
    │   Supabase   │  │    FastAPI 앱   │
    │  (데이터베이스│  │  (AI 두뇌·규칙) │
    │   + 인증)    │◄─┤                 │
    └──────────────┘  └────────┬────────┘
                                │
                       ┌────────▼────────┐
                       │   AI (OpenAI)   │
                       │  Review 생성    │
                       └─────────────────┘
```

**역할 분담:**
- **Next.js**: 사용자가 보는 화면을 그리고, 데이터를 직접 읽어옴
- **FastAPI**: AI 호출, 데이터 저장, 비즈니스 규칙 처리
- **Supabase**: 모든 데이터 저장소 + 로그인 처리 + 파일 저장 + AI 검색(약관)

---

## AI Review가 만들어지는 과정

사용자가 영수증을 올리면 즉시 결과가 나오지 않습니다. 백그라운드에서 처리되며 완료되면 화면이 자동으로 업데이트됩니다.

```
영수증 업로드
    ↓
"분석 중" 상태 표시 (즉시)
    ↓  (백그라운드)
내 보험 정보 조회
    ↓
관련 약관 검색
    ↓
AI에게 분석 요청
    ↓
Review 리포트 저장
    ↓
화면 자동 업데이트 → Review 확인
```

이렇게 설계한 이유: AI 분석은 시간이 걸릴 수 있어서, 사용자가 기다리는 동안 화면이 멈추지 않도록 분리했습니다. 또한 영수증 저장과 AI 처리를 분리해, AI 분석이 실패해도 업로드한 파일은 안전하게 보존됩니다.

## 확장 설계

보험 이후 다른 도메인을 추가하는 방식:

```
Decision OS 플랫폼
    │
    ├── 공통 인프라 (계정, 루프, 데이터 저장)
    │
    ├── 보험 Playbook  ← 지금 만드는 것
    ├── 커리어 Playbook  ← 향후
    ├── 투자 Playbook    ← 향후
    └── 주거 Playbook    ← 향후
```

각 Playbook은 자체 데이터(보험 계약, 커리어 이력 등)를 가지지만, Review→Decision→Outcome 루프와 계정 시스템은 공유합니다. 새 Playbook 추가 시 기존 코드를 바꾸지 않고 새 모듈만 추가합니다.

## MVP 범위

**지금 만드는 것 (보험 Playbook v1):**
- 계정 생성·로그인
- 보험 정보 수동 입력
- 청구 이력 입력
- **핵심: 병원 영수증 → 청구 가능 보험 AI 분석**
- 결정 기록 및 대시보드

**다음 단계:**
- 보험 갱신 검토 Review
- 중복 보장 분석 Review
- 커리어 Playbook

**의도적으로 나중으로 미룬 것:**
- 보험사 직접 연동 (데이터 자동 수집)
- 보험 상품 비교·추천 서비스
- 팀/가족 공유 기능
- Memory 시스템

## 기술 선택 배경

| 선택 | 이유 |
|------|------|
| Next.js | 모바일·데스크탑 웹 동시 지원, 국내외 표준 프레임워크 |
| FastAPI (Python) | AI/LLM 연동 생태계가 Python에 집중됨 |
| Supabase | 데이터베이스·인증·파일·AI 검색을 한 곳에서 관리 |
| Railway | 간단한 배포, 프론트·백 동일 플랫폼에서 관리 |
| OpenAI (MVP) | AI 공급자는 나중에 교체 가능하도록 추상화, 지금은 가장 빠른 선택 |
