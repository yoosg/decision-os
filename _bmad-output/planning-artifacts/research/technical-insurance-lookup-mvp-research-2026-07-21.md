# 기술 리서치: 보험 조회 MVP 구현 전략

**작성일:** 2026-07-21  
**작성자:** Sgyoo  
**리서치 유형:** Technical

---

## 리서치 개요

Decision OS는 보험 조회 자동 연동을 핵심 온보딩 기능으로 계획하고 있다. 그러나 PRFAQ에서 "API 파트너십 협상 현황과 타임라인 미정"으로 높은 리스크 항목으로 분류된 이 기능이 MVP 단계에서 실제로 어떻게 구현 가능한지를 조사했다.

**핵심 질문:** 마이데이터 사업자 허가(자본금 5억+, 6~12개월 심사) 없이 보험 가입 현황을 조회할 수 있는 합법적이고 현실적인 경로는 무엇인가?

---

## 규제 현황 (2026 기준)

### 스크래핑은 불법

2022년 1월 마이데이터 제도 시행 이후, **마이데이터 미허가 업체가 스크래핑 방식으로 보험 조회 서비스를 제공하는 것은 불법**이다. 허가를 받은 28개사만 스크래핑 방식으로 금융사 서버에 접근할 수 있다.

이전에는 인슈어테크 기업들이 스크래핑으로 보험 조회·진단 서비스를 제공했으나, 현재는 허가 없이 동일한 방식을 사용하면 신용정보법 위반이다.

### 보험업권 마이데이터 참여 저조

2026년 현재 금융 마이데이터 사업자 중 보험업권 참여는 전체의 **5% 미만 (약 3개사)**에 불과하다. 금융 마이데이터가 자산·부채·소비패턴 데이터 중심이라 보험 리스크 평가에 필요한 건강·질병 데이터와 미스매치가 발생하기 때문이다.

마이데이터 2.0은 2025년 6월 출범했으며, 뱅크샐러드가 2025년 6월 19일 2.0 인프라를 정식 도입했다.

## MVP 구현 옵션 분석

### 옵션 1: CODEF API (추천 — 즉시 활용 가능)

**CODEF**는 마이데이터 허가 없이 이용 가능한 합법적 금융 데이터 중개 API 플랫폼이다.

**지원 보험 서비스:**
- 생명보험협회 **내보험찾아줌** 연동 (보험금 미청구 조회)
- 신용정보원 **내보험다보여** 연동 (가입 보험 계약 조회)
- 자동차보험 정보 조회
- 보험개발원 차 보험료 할인할증 조회

**작동 방식:**  
사용자가 자신의 금융기관 ID/PW를 입력 → CODEF가 해당 기관 시스템에 사용자 자격으로 접근 → 데이터 반환. 이는 사용자 위임 접근으로, 마이데이터 규제의 허가 요건과 별개로 운영된다.

**장점:**
- 즉시 연동 가능 (허가 절차 없음)
- 구독형 SaaS 모델 → 초기 비용 낮음
- `developer.codef.io`에 개발 가이드 제공

**단점:**
- 사용자가 보험사/내보험다보여 ID·PW를 직접 입력해야 함 → 마찰 있음
- CODEF의 서비스 연속성에 의존
- 마이데이터 API 방식보다 데이터 범위 제한될 수 있음

**개발자 포털:** [developer.codef.io/products/insurance/overview](https://developer.codef.io/products/insurance/overview)

### 옵션 2: 공공 마이데이터 이용기관 등록

**행정안전부 공공 마이데이터**는 별도 허가 없이 이용기관으로 등록하여 공공기관 데이터를 연동할 수 있다.

**보험 관련 제공 데이터 (2024년 9월~ 적용):**
- 자동차 사고 보상청구 지원
- 증권계좌 한도해제

**접근 방법:**  
사용자가 공공 마이데이터 전송요구권을 행사 → 이용기관(Decision OS)이 해당 데이터 수신. 민감 개인정보를 사용자 동의 기반으로 수집하는 가장 안전한 법적 구조다.

**장점:**
- 허가 절차 없이 이용기관 등록만으로 가능
- 법적 리스크 최소
- 건강보험공단, 국민연금 등 공공데이터 연동 확장 가능

**단점:**
- 민간 보험사 가입 계약 목록은 포함되지 않음 (공공기관 데이터만)
- 보험 청구 결정 지원에 필요한 민간 보험 약관·가입 내역 조회 불가

**공식 포털:** [adm.mydata.go.kr](https://adm.mydata.go.kr/intro/addHelpPage.do?type=index)

### 옵션 3: 마이데이터 허가 사업자 B2B 파트너십

기허가된 마이데이터 사업자(뱅크샐러드, 토스 등)와 B2B 파트너십을 맺어 보험 데이터를 간접 수신하는 경로다.

**주요 후보:**
- **뱅크샐러드**: 금융 + 건강 마이데이터 결합. 2025년 6월 마이데이터 2.0 도입. 2026년 하반기 코스닥 상장 목표. → 파트너십 협상 가능성 있음
- 기타 핀테크 플랫폼

**장점:**
- 마이데이터 정식 API로 포괄적인 보험 가입 데이터 수신 가능
- 장기적으로 가장 완성도 높은 데이터 품질

**단점:**
- 협상 기간 및 비용 불확실
- 파트너사 의존도 높음 (사업 지속성 리스크)
- 파트너사가 경쟁 서비스로 발전할 가능성

---

### 옵션 4: 마이데이터 직접 허가 취득

금융위원회에 본인신용정보관리업(마이데이터) 허가를 직접 신청하는 경로.

**조건:**
- 자본금 5억 원 이상
- 심사 기간 6~12개월
- 전산 보안 요건, 개인정보 처리방침 등 엄격한 요건

**결론:** MVP 단계에서 비현실적. 시리즈 A 이후 본격 검토 수준.

---

## MVP 권장 전략

```
Phase 1 (MVP, 0~6개월)
  └── CODEF API로 내보험다보여 연동
      사용자: ID/PW 입력 → 가입 보험 목록 조회
      
  └── 공공 마이데이터 이용기관 등록
      건강보험공단 데이터 등 공공 데이터 보완

Phase 2 (PMF 확인 후, 6~18개월)
  └── 마이데이터 허가 사업자 B2B 파트너십 체결
      뱅크샐러드 또는 핀테크 플랫폼과 계약

Phase 3 (스케일업, 18개월+)
  └── 마이데이터 직접 허가 취득 검토
```

### 핵심 고려사항

**UX 마찰 문제:**  
CODEF 방식은 사용자가 내보험다보여 ID/PW를 직접 입력해야 한다. 이는 온보딩 이탈률에 직접 영향을 미치므로, 입력 단계를 최소화하는 UX 설계가 필수다.

**데이터 범위 한계:**  
CODEF + 공공 마이데이터 조합으로는 일부 소규모 보험사나 공제조합 상품이 누락될 수 있다. 출시 전 지원 보험사 목록을 명확히 공시해야 한다.

**법적 리스크 모니터링:**  
CODEF API를 통한 보험 조회가 현재 합법이지만, 금융위원회의 마이데이터 정책 변화에 따라 규제가 강화될 수 있다. 계약 조건에 서비스 연속성 보장 조항 필요.

## 보험 조회 UX 설계

### 핵심 문제: 자격증명 입력이 가장 큰 이탈 지점

CODEF API 방식은 사용자가 내보험다보여 ID/PW를 직접 입력해야 한다. Plaid(미국 계좌 연동 서비스)의 실측 데이터에 따르면 **credential 기반 연동 플로우의 이탈률은 20~88%**다. Decision OS 온보딩에서 이 단계가 전환율의 최대 위협이다.

KYC 절차가 5분을 초과하면 완료율이 **40% 하락**한다는 연구 결과도 있다. 보험 연동 플로우 전체를 3분 이내로 설계하는 것을 목표로 삼아야 한다.

---

### 국내 레퍼런스 분석

**카카오페이손해보험**  
카카오톡 내에서 가입~청구를 완결하는 구조다. 기존 카카오 계정으로 모든 인증이 처리되므로 ID/PW 입력 마찰이 제로에 가깝다. 3년 만에 가입자 600만 명을 확보한 핵심 원인이 여기 있다. Decision OS는 카카오처럼 기존 슈퍼앱에 얹힐 수 없으므로, 다른 방식으로 마찰을 낮춰야 한다.

**보맵**  
첫 화면이 연동 요청이 아닌 **"보장핏팅" 질문 플로우**다. 성별·나이·소득·건강 상태를 간단한 질문으로 수집한 뒤, 연동 없이도 보장 분석 결과를 먼저 보여준다. 이후 "실제 내 보험을 연동하면 더 정확해요"로 연동을 유도하는 구조다. 마이데이터 연결 시간 단축을 위한 플로우 개선도 지속 진행 중이다.

**토스**  
단순함이 차별점이다. 한 화면에 하나의 행동. 복잡한 보험 정보를 어떻게 단순하게 표현할지가 토스 UX의 핵심 고민이다.

---

### 글로벌 레퍼런스: Plaid의 교훈

Plaid는 계좌 연동 UX를 수년간 최적화하며 다음을 발견했다:

- 보안 인증 마크를 **입력 필드 바로 옆에 배치**하면 자격증명 입력 의향 **31% 증가**
- OAuth 팝업 방식 전환으로 모바일 전환율 **~11% 상승**
- "우리는 당신의 비밀번호를 저장하지 않습니다" 명시 → 신뢰도 향상
- 필요한 데이터만 요청 (불필요한 권한 요청 금지)
- 작은 UX 개선만으로도 온보딩 성공률 **20~40% 향상** 가능

---

### Decision OS 권장 온보딩 플로우

**현재 가정하는 패턴 (위험):**
```
앱 설치 → 즉시 내보험다보여 ID/PW 요구 → 대규모 이탈
```

**권장 패턴 — "가치 먼저, 연동 나중":**
```
1단계: 앱 설치 → 이름/나이/성별만 입력 (30초)

2단계: 보험 건강도 추정치 미리보기
        "한국 30대 평균 보험 6건, 월 보험료 18만원"
        "내 실제 보험을 연동하면 정확한 분석을 받을 수 있어요"

3단계: [지금 연동하기]  [나중에 연동하기]
        ↓ 선택
        
4단계: 신뢰 신호 화면 (연동 선택 시)
        ✓ "비밀번호는 저장되지 않습니다"
        ✓ 금융보안원 인증 마크
        ✓ "평균 연동 시간: 30초"
        ✓ "연동 후 평균 발견 미청구 보험금: 43만원"

5단계: 내보험다보여 ID/PW 입력
```

**수동 입력 대안 경로 (필수):**  
연동에 실패하거나 거부하는 사용자를 위해 "직접 입력하기" 경로를 반드시 제공해야 한다. 보험사명·상품명·월 보험료를 텍스트로 입력하는 방식으로, 보맵이 초기 사용자 확보에 이 방식을 활용했다. 연동 없이도 핵심 기능(AI Review 생성)이 동작해야 한다.

---

### UX 설계 체크리스트

- [ ] 연동 요청 전에 구체적 가치 수치를 먼저 보여주기
- [ ] KYC 전체 플로우 3분 이내 완료 목표
- [ ] 보안 신뢰 신호를 입력 필드 **바로 옆**에 배치
- [ ] "나중에 연동하기" 옵션 항상 제공 (강제 연동 금지)
- [ ] 수동 입력 대안 경로 제공 (연동 없이도 핵심 기능 동작)
- [ ] 연동 실패 시 명확한 오류 메시지 + 수동 입력으로 fallback
- [ ] 연동 완료 직후 즉각적인 가치 제공 (보험 건강도 점수 표시)
