- (decision) Product: Decision OS — AI가 검토하고 사용자가 결정하는 의사결정 운영체제. 보험이 첫 MVP Playbook.
- (decision) Core loop: Context → Review → Decision → Outcome → Memory → Next Review. 챗봇 아님, 결정 관리 시스템.
- (decision) Home = Inbox 패러다임. 중앙 Chat 입력창 없음. 새 Review 확인이 primary 진입 이유.
- (decision) Chat은 보조 기능. Review 상세·Project 상세·Event 정보 보완 context 안에서만 진입.
- (decision) Decision 옵션 3가지 고정: 채택 / 보류 / 무시 (원탭).
- (decision) AI Review 필수 구성: 결론 + 근거 + 위험 + 불확실한 정보 + 추천 다음 단계 + 데이터 기준 시점.
- (decision) 자동화 원칙: 외부 데이터/AI는 Event 후보 생성만. 사용자 확인 후 Project 반영. 자동 확정 없음.
- (decision) 입력 우선순위: 외부 연동 → 기존 Project Context → OCR → 선택형 → 짧은 자유 → 긴 자유 입력.
- (decision) 시각 방향: 금융 서비스 신뢰감 + 생산성 도구 명료함 + 헬스케어 상태 가시성. 모바일 우선. 카드 기반이나 카드 남용 금지. 과도한 AI 네온/그라데이션/챗봇형 UI 금지.
- (decision) UX 원칙: One screen one decision (Primary CTA 1개). Review before Action. Chat is not primary. Minimize anxiety.
- (decision) MVP 주요 화면: Onboarding, 보험 조회/등록, Home/Inbox, Insurance Project 상세, Review 상세, Decision, 영수증 업로드, OCR 확인, Claim Review, Memory Timeline, Profile/Integration.
- (decision) 핵심 MVP 플로우 성공 기준: 보험 등록 → Review 확인 → Decision → 병원 Event 등록 → 청구 Review → Outcome 기록 자연스러운 완료.
- (decision) 온보딩 UX: 가치 먼저 보여주고 연동 유도. 강제 연동 금지. 수동 입력 대안 경로 필수. KYC 3분 이내 목표.
- (decision) Tech stack: Next.js + FastAPI + Supabase + Railway. 모바일 웹 우선, 데스크탑 웹 지원.
- (decision) Home 화면 구조: Home 안의 Inbox 섹션 패턴. 최상단 = Inbox (새Review > Event후보 > 진행중Action). 그 아래 Project 요약 + 최근 Outcome. Inbox 항목 다수시 '전체보기' → 별도 Inbox 목록 화면.
- (decision) 모바일 하단 탭: 홈 | 프로젝트 | + | 메모리 | 프로필 (5탭). + = Event 등록 Bottom Sheet (영수증촬영 / 병원방문등록 / 보험정보추가 / 기타기록). + 는 Chat 버튼 아님.
- (decision) MVP + Bottom Sheet 항목 우선순위: 1) 병원 영수증 촬영 (MVP에서 강조), 2) 병원 방문 직접 등록, 3) 보험 정보 추가, 4) 기타 상황 기록.
- (decision) 주인공 여정 확정 - 박지은(35세 직장인, 피곤한 상태): + → 영수증 촬영 → OCR 확인(진료일 수정) → Event 후보 확인 → Insurance Project 반영 → 백그라운드 분석 → Home Inbox에 Review 등장 → Review 열기(청구가능 2건, 서류목록, 불확실정보) → 청구 준비 시작 Decision → 서류 Checklist → 외부 청구 → 결과 대기 → Inbox에 Outcome 입력 요청 → 72,000원 지급 기록 → Memory 저장.
- (decision) 박지은 핵심 가치: 약관 직접 찾지 않아도 됨 / 상황 설명 입력 불필요 / 서류 준비 즉시 안내 / 과거 결과 학습 반영.
- (decision) Decision 화면: '청구 준비 시작' 선택 → 서류 Checklist → 상태 = 결과 확인 대기. 며칠 후 Inbox: Outcome 입력 요청.
- (decision) Push notification: MVP 포함. 트리거: 새 Review 생성 / Event 후보 생성 / Outcome 입력 요청 / Decision 후속 Action 필요. 제외: 단순 분석 완료, 마케팅, 반복 리마인드.
- (decision) Push 동선: Push → Deep Link → Home(Inbox) → 해당 Review/Event 직행. Notification Center 별도 없음, Inbox가 알림 역할 겸임.
- (decision) 알림 권한 요청: 온보딩에서 가치 증명 후 (보험 건강도 확인 직후 S03) 요청. 강제 요청 금지.
- (decision) 알림 무시 UX: Inbox에 항목 유지. 중복 푸시 없음. 일정 기간(예: 3일) 후 1회 추가 리마인드만 허용.
- (decision) 시각 레퍼런스 확정: Cal AI (전체 디자인 언어, 타이포, 여백, 온보딩) + Linear (Inbox, 우선순위, 상태) + Apple Health (상태 요약, 건강도 시각화) + Copilot Money (금융 카드). ChatGPT형 Chat UI 및 보험사 홈페이지 스타일 금지.
