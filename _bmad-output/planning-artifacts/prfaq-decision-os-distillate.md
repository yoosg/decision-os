## 제품 포지셔닝

- Decision OS는 보험 앱이 아니라 의사결정 운영 체제(Decision Operating System)다. 보험은 첫 번째 Playbook.
- 핵심 차별화: "AI가 검토하고, 사용자가 결정하고, 결과를 함께 기억한다" — 챗봇과 달리 기억이 축적됨
- 기각된 포지셔닝: "보험 관리 앱", "AI 보험 어시스턴트", "챗봇" — 모두 기존 경쟁자와 동일선상
- 경쟁 공백: 한국에 Review→Decision→Outcome→Memory 전 사이클을 닫는 소비자 앱 없음
- 토스보험/보험다보여는 "무엇을 가입했는지" 보여줌 → Decision OS는 "지금 어떻게 해야 하는지" + "기록" 제공

## 핵심 고객 및 문제

- 타겟: 보험을 다수 보유한 한국 소비자 (병원 방문, 보험 갱신 등 이벤트 발생 시 결정을 못 내리는 사람)
- 핵심 고통: 보험료는 내지만 청구 타이밍과 방법을 모름 → 수령 가능한 보험금 미청구로 경제적 손실
- 행동 패턴: 평상시 앱 거의 미사용, 이벤트 발생 시 결정 필요 → 이벤트 드리븐 제품이어야 함
- 구체적 경제적 스테이크: 1회 이벤트당 수백만 원 수준의 보험금 (예: 320만 원) 누락 가능
- 기존 AI 챗봇의 한계: 기억 없음, 누적 없음, 결정 이력 없음

## 핵심 플로우 (변경 불가 설계 결정)

- Context → Review → Decision → Outcome → Memory → Next Review (모든 Playbook에 동일 적용)
- Decision 옵션: 채택 / 보류 / 무시 (3가지 고정, UX 단순성 + 의도 분리 동시 달성)
- AI 역할: 답변자가 아닌 검토자(Reviewer) — 사용자는 결정자(Decision Maker), AI는 대신 결정 금지
- Memory 구조: Context + Review + Decision + Reason + Outcome + Retrospective 저장
- 이벤트 트리거: 보험 갱신, 약관 변경, 병원 방문, 청구 완료, 수동 요청

## MVP 범위 (확정)

**포함:**
- 보험 자동 조회 (myData/보험 API)
- AI Review 생성 (LLM 기반)
- 보험금 청구 지원 (서류 안내, OCR 영수증 처리)
- Decision 저장 (채택/보류/무시)
- Outcome 기록 및 Memory 저장

**제외 (Non-Goals):**
- 자동 보험금 청구 (보험사 자동 제출)
- 완전 자동 이벤트 감지 (OCR + 사용자 확인으로 대체)
- AI가 사용자 대신 결정
- 다중 Playbook 동시 출시 (Career, Investment 등)
- 보험사별 심사 자동화

## 기술 컨텍스트

- 외부 연동: 보험 조회 API (myData 또는 마이데이터 파트너), OCR (영수증 처리), LLM (Review 생성)
- 마이데이터 경로: 직접 허가(금융위원회, 자본 5억+, 6-12개월) vs. 기허가 사업자 파트너십 (MVP에서 현실적 경로)
- LLM 한국어 처리: 2025-2026 기준 충분히 성숙, 저비용 Review 생성 가능
- 아키텍처: Decision Engine (도메인 공통) + Playbook (도메인 특화) 분리 — 향후 Career/Investment 확장 전제
- OCR 의도: 입력 피로 최소화용 (완전 자동화 목적 아님, 사용자 확인 단계 유지)

## 화면 구조

- Home: 새로운 Review + 최근 Decision/Outcome + 프로젝트 목록
- Project: 보험 건강도 (점수) + 월 보험료 + 보험 개수 + 다음 Review + 최근 변경사항
- Review: 현재 상황 + AI 판단 + 근거 + 위험 요소 + 추천 Action
- Decision: 채택/보류/무시 (원탭)
- Memory: 시간순 Review→Decision→Outcome 타임라인

## 경쟁 인텔리전스

- 카카오페이보험: 슈퍼앱 내 유통 강점, 2025 글로벌 인슈어테크 어워드 수상. 구매·가입 집중, 결정 지원 없음
- 토스보험: 정책 집계·비교, 가시성 제공. 행동 유도 없음, AI 없음
- 보험다보여: FSC API 기반 보험 조회·요약. 읽기 전용 대시보드, 결정 지원 없음
- 글로벌 AI 보험 플랫폼 (Majesco, Shift Technology): B2B 보험사용 도구, 소비자향 없음
- 미국 Origin AI: 지속 메모리 기반 재무 의사결정 지원 — 가장 유사한 글로벌 선례, 한국/보험 특화 없음

## 시장 컨텍스트

- 한국 보험 시장: 2033년 USD 280B 전망, 아시아 최고 보험 침투율 국가 중 하나
- 글로벌 인슈어테크: 2025년 USD 36B → 2035년 USD 739B (CAGR 35%)
- AI 채택: 2024→2025년 한국 보험사 AI 본격 도입 비율 8%→34% 급증
- 소비자 Pain: 한국 보험 불만의 28%가 지연·소통 부재, 20%가 투명성 요구

## 미결 고리스크 항목 (PRD 진입 전 해결 필요)

1. **FSC 규제 해석** (최고 우선순위): "AI 청구 권장"이 보험업법상 무허가 보험 모집/자문에 해당하는지 — 출시 전 법무 자문 및 FSC 사전 질의 필수
2. **마이데이터 파트너십 경로**: 기허가 마이데이터 사업자와 파트너십 협상 현황 — MVP Critical Path
3. **수익 모델 결정**: 구독, B2B SaaS, API 화이트레이블, 광고/추천 중 방향 — PRD 우선순위에 영향
4. **배급 전략**: 독립 앱의 구조적 CAC 열세 대응 — 파트너십 채널(병원, HR 플랫폼) 또는 B2B2C 구체화

## 미결 미정 항목 (PRD에서 결정 필요)

- AI Review 허용 오류율 및 출시 기준 (정확도 임계값)
- 초기 전문가 검수 비율 및 운영 모델
- PIPA 준수 아키텍처 (건강 + 금융 데이터 동시 처리)
- 지원 보험사 범위 (API 미지원 보험사 처리 방식)
- 데이터 내보내기 / 계정 탈퇴 정책
- 팀 구성 및 MVP 타임라인 (마이데이터 파트너십 협상 완료 후 산정 가능)

## 버딕트 요약

- **강철**: 차별화 포지셔닝 명확, 실제 고통 타겟, 기술적 타당성, 경쟁 공백, 시장 타이밍
- **더 달궈야 할 것**: 수익 모델, 배급 전략, AI Review 정확도 기준, 사용자 신뢰 획득 전략
- **균열 (출시 전 필수 해결)**: FSC 규제 리스크, 마이데이터 API 파트너십 타임라인, "AI 오류 시" 신뢰 체계

## PRD 팀을 위한 권고사항

- PRD 작성 전 법무팀 FSC 규제 검토를 완료할 것
- 마이데이터 파트너십 또는 직접 허가 경로를 결정할 것 (개발 타임라인의 선행 조건)
- 수익 모델 결정 후 PRD 우선순위 반영
- "AI Review는 참고 정보, 결정은 사용자" 원칙을 UX 법적 고지에 명확히 반영
- 초기 KPI: 보험 자동 연동 성공률, Review 생성 건수, Decision 완료율, Outcome 입력율, 사용자당 누적 Memory 건수
